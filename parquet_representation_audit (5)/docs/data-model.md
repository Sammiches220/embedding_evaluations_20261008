# Data model and feature meanings

## Rows and identity

The Parquet file is a table: one row per item and one column per source value. All feature columns share that row order. Declare a stable exact ID column (`string`, `integer`, or `boolean`) so the report can trace samples and align external embeddings. IDs are identifiers, not measurements: do not cast them to floats. Composite IDs can be declared as multiple identity columns.

If embedding vectors live outside the Parquet table, provide a real numeric `N × D` NumPy matrix and a one-dimensional ID array for its rows. The IDs are joined by exact identity. If vectors are in Parquet, declare their numeric list column and fixed dimension. Each embedding model has a fixed declared dimension; two compared models may have different dimensions.

## Choose the feature kind that matches the source

| Kind | Value in one row | Use it for | Meaning-changing choices to avoid |
| --- | --- | --- | --- |
| `numeric` | Finite real scalar | Continuous or engineered measurements, including signed values | Binning or rounding changes the feature; keep the raw values unless bins are the intended feature |
| `count` | Nonnegative integer | Event counts or nonnegative quantities | Negative values and fractions are not counts; use `numeric` when those are meaningful |
| `categorical` | One exact scalar label | Nominal classes | Integer-looking labels are still categories unless their order has meaning |
| `cluster_label` | Exactly one cluster ID | A disjoint clustering, one assigned cluster per item | Do not split one clustering into indicator columns or convert labels to an ordinal scale |
| `ordinal` | One category plus an explicit order | Rating levels or other ordered categories | The order is an assumption; do not use for arbitrary category IDs |
| `boolean` | True or false | Binary state | Missing is different from false |
| `multilabel` | A list/set of string labels, or explicitly encoded string | Tags that can co-occur on one item | Do not convert a multi-label set into one exclusive class |
| `text` | Scalar string | Source description only | It is not analyzed geometrically without an explicitly derived feature |
| `datetime` | Timestamp | Source time, optionally with declared derived time features | A derived year/month/day is a new coarser feature, not a lossless replacement for the timestamp |

Each clustering or engineered feature is an independent column. A Parquet row can therefore contain `cluster_a`, `cluster_b`, `score`, `age_seconds`, and `tags` together. The audit does not require all features to share one label vocabulary or to form a partition of the dataset.

## Missingness, types, and conversion

Null means unknown or unavailable. For multilabel data, an empty list means known to have no labels; null means label membership is unknown. Configure declared sentinel values only when the data producer uses them for missingness. `false`, `0`, and an empty set are valid observed values by default.

The loader retains values as objects through type checks to avoid Pandas silently promoting nullable integer IDs to floats. Conversions are opt-in and deliberately narrow. For example, string-to-integer conversion accepts only exact integer text; string-to-number conversion must be declared and still rejects booleans and non-finite values. Nested Arrow values require an explicit struct path or multilabel encoding. Errors identify the feature and batch row instead of silently guessing.

## Is the translation lossless?

A direct semantic mapping is generally possible when each source feature already has a scalar or tag-set interpretation: map it directly to the matching kind without changing values. A numeric column should remain numeric; a disjoint cluster assignment should remain one cluster ID; tags should remain a set per item.

Some transformations are intentionally lossy. Binning numeric measurements, collapsing rare categories, assigning arbitrary numbers to nominal categories, dropping tags, or reducing timestamps to calendar parts removes distinctions. The prompt generated by `inspect` tells the preparer to preserve raw values and explicitly list any unavoidable conversion. If a feature cannot be represented without changing its meaning, leave it out or derive a separately named feature and document the choice.

See [information preservation and limits](information-preservation.md) for the distinction between source preservation, numeric precision, vocabulary restrictions, and complete analytical coverage.
